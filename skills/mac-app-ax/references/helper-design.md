# 동작을 헬퍼 함수로 묶기

틀: [templates/helper_action.swift](../templates/helper_action.swift).

## 왜 묶는가

에이전트가 기본 도구로 하면 "요소 찾기 → 입력 → 누르기 → 다시 확인"을 단계마다 따로 호출한다.
호출마다 모델이 결과를 읽고 다음을 정하므로 느리고, 중간에 창이 바뀌면 엉뚱한 곳을 누른다.
헬퍼는 같은 일을 네이티브 코드 안에서 한 번에 끝내고 JSON 한 줄만 돌려준다
(`kakaotalk-ax`에서는 보내기 한 번이 에이전트 업무 호출 여러 번에서 헬퍼 1번이 되었다).

## 구조

```
Python/Node 래퍼 (인수 검사 · 잠금 · 요청 기록 · 재확인)
  └─ 네이티브 브리지 (Swift, stdin JSON → stdout JSON)
       ├─ 권한 · 앱 실행 확인
       ├─ 대상 창 정확히 하나 찾기
       ├─ 요소 찾기 (매번 새로, 유일성 검사)
       ├─ 전제 확인 (모달 없음 · 초안 없음 · 버튼 활성)
       ├─ 동작 한 번
       └─ 결과 JSON (status, reason, actions, dispatchAttempted, elapsedMs)
```

Swift를 쓰는 이유: `ApplicationServices`의 AX C API를 바로 부르고, 바이너리 하나로 빠르게 뜬다.
래퍼는 소스 해시로 바이너리를 캐시해 처음 한 번만 컴파일한다.

## 규칙

- **브리지를 역할별로 나눈다**: 읽기 전용 · 화면 이동(열기 · 닫기 · 검색) · 되돌릴 수 없는 동작(보내기).
  읽기 브리지는 값을 바꾸거나 동작을 부르는 코드 자체를 갖지 않는다. 보내기 브리지는 `AXPress`를 부르는 곳이 한 군데뿐이다.
- **유일성**: 대상 창 · 버튼 · 입력창이 정확히 1개일 때만 진행한다. 아니면 `*_not_unique` · `*_ambiguous`로 멈춘다.
  동명 대상을 임의로 고르지 않는다.
- **멈출 조건**: 모달(`AXSheet` · `AXDialog`, 창의 `AXSheets`)이 떠 있음, 입력창에 사용자가 쓰던 초안이 있음,
  버튼이 비활성, 대상 창이 앱의 메인 창임. 사용자가 하던 것을 덮어쓰지 않는다.
- **다시 찾기**: 값을 바꾼 뒤에는 요소를 다시 찾아 전제를 다시 확인하고 동작한다. 이전 요소를 믿지 않는다.
- **한도**: `AXUIElementSetMessagingTimeout(app, 0.2~0.5)`, 전체 마감(예: 8초), 방문 노드 수 한도.
  넘으면 `*_limit`으로 멈춘다. 응답 없는 앱 때문에 에이전트가 멈추지 않게 한다.
- **필요 없는 곳은 내려가지 않는다**: 보내기 브리지는 대화 목록 표(`AXTable` · `AXRow` · `AXCell`)에 들어가지 않는다.
  읽기 브리지는 입력창(`AXTextArea`)의 값을 읽지 않는다. 읽은 적 없는 것은 새지 않는다.
- **텍스트 전달**: 사용자 텍스트는 명령 인자가 아니라 stdin JSON으로. 셸 따옴표 문제와 프로세스 목록 노출을 막는다.
- **잠금**: 화면을 바꾸는 동작은 프로세스 간 파일 잠금(`flock`)으로 하나씩. 다른 호출이 쓰는 중이면 기다리지 말고 바로 알린다.
  본문 읽기처럼 화면을 안 바꾸는 것은 창별로 병렬로 돌려도 된다.
- **이유 코드**: 실패는 짧은 영어 코드(`target_window_not_open`, `existing_draft_preserved`)로. 에이전트가 다음 행동을 고를 수 있다.
- **읽기 결과에 범위를 적는다**: "보이는 행만", "앱이 보고한 전체 수", "더 있음(hasMore)이 전체 기록의 끝을 뜻하지 않음".
  모르는 값(작성자 · 생략된 시각)은 추측하지 말고 `null`로 둔다.

## 함수 목록 정하기

사용자가 자주 하는 일 단위로 정한다. 카카오톡 사례의 12개:
창 목록 · 방 목록 · 방 검색 · 열기 · 닫기 · 읽기 · 여러 방 읽기 · 이전 대화 요청 · 본문 검색 · 검색 닫기 · 보내기 · 보내기 결과.
여러 대상에 같은 일을 하는 것(여러 방 읽기)은 헬퍼 안에서 열기는 순서대로, 읽기는 병렬로 처리해 한 함수로 낸다.
에이전트가 스레드 · 반복 코드를 따로 짜지 않게 한다.
